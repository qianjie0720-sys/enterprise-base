# PostgreSQL 原生恢复程序（P3-G2）

`deploy/restore_postgres.py` 是完整恢复入口的内部模块，暂不提供独立操作命令。调用方必须先用 `restore_guard.prepared` 完成整包解密、SHA256 校验、新项目检查，并在同一独占锁中建立隔离目标，再调用本模块；这部分不代表 `make restore` 全套入口已完成。

程序再次核对新旧三组 Compose 项目名不重叠、所有应用与临时任务已停写，目标 PostgreSQL 容器标签、健康状态、实际镜像 ID 与备份一致，数据命名卷属于新项目。来源项目或共享旧卷一律拒绝。Qdrant 的快照恢复由后续步骤处理，此模块不会停止或启动任何服务。

索引中的每个数据库（含插件库和 postgres）都用原生 `pg_restore` 恢复。数据库已存在时必须不含用户表、视图、序列等关系；全部预检后才创建缺少的库。备份文件必须是私有非空普通文件，通过标准输入送入容器，不另留容器内明文 dump。

数据库对象归目标 `POSTGRES_USER`；使用目标容器现有身份，不执行 `postgres-globals.sql`，不恢复源 owner、ACL、角色密码或表空间路径。该 globals 文件仍随加密备份保留供审计；自定义数据库角色/授权需要另外审查，不自动导入。每库事务内恢复，任何错误立即停止，失败目标不得接流量，须由操作者确认后清理并重建新项目。原环境不受影响。

本机与 CI 的命令协议测试覆盖全部数据库、拒绝脏库/旧项目/运行中的应用/旧卷/错误镜像、失败停止和输出脱敏，另用真实子进程核对文件标准输入。它们没有启动真实 PostgreSQL；Dify 应用、知识库与插件库的实际恢复及耗时仍由 Claude 云端联测记录，服务器截图待补。没有新增依赖。
